# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [0.99.69] — 2026-11-18

### Added

- **Восстановление vault**: `--restore --vault --to DIR [--at YYYY-MM-DD]
  [--from NAME]`. Берётся последний base ≤ даты, применяются следующие
  манифесты, скачиваются только нужные тома; удалённые файлы не
  восстанавливаются, права/владелец/mtime — из манифеста.
- Порядок восстановления — `vault.restore_order` (`desc` по умолчанию,
  приоритет каталогов внутри слоя).

## [0.99.68] — 2026-11-18

### Added

- **Задача `vault`**: версионный бэкап файлов неизменяемыми TAR-слоями и
  JSON-манифестами. Первый запуск `--vault --full` создаёт base, дальше идут
  дельты по журналу `YYYY-MM-DD.journal.txt` или по полному скану
  (`journal.type: scan`). Каждый запуск создаёт слой, даже пустой.
- **Транспорты апстримов**: `type: rclone|rsync`, `bwlimit`, `host`,
  `ssh_options`; `rsync` пока разрешён только задаче `vault`.
- **`--full` и `--reconcile`** для vault; `--full` начинает новую цепочку
  и закрывает журналы до даты запуска, `--reconcile` делает корректирующий
  слой без нового base.

### Changed

- Локальный sqlite-индекс `state_dir/index.sqlite` ускоряет diff и
  восстанавливается из удалённых манифестов при потере.
- `rclone` получает `--bwlimit` из апстрима.

### Осталось

- `--list`, `--verify` и `--restore` для vault — следующий шаг.

## [0.99.64] — 2026-11-17

### Added

- `storage.allow_empty` (по умолчанию `false`): `sync` отказывается работать
  из пустого каталога-источника — защита от «диск не смонтировался».
- `database.ignore_table`: `--ignore-table` для mysql/mariadb (без точки —
  к текущей базе) и `--exclude-table` для postgres.
- `examples/logrotate.d/kwbackup`; пример ставится и в `.deb`.
- `--check` теперь возвращает `1` при проблемах preflight и уведомляет об этом
  при `notify.on: [failure]`.

### Changed

- `database.args` дополняет дефолтные опции дампа, а не заменяет их.
- preflight проверяет `rclone` для всех задач, включая дампы БД.

## [0.99.62] — 2026-11-16

Сводка с первой Python-версии. Пошаговая история, запись на каждый коммит, —
в [`debian/changelog`](debian/changelog); этот файл обновляется сводно.

### Added

- **Инкрементальная задача** (`-i/--incremental`): цепочки GNU tar, полный
  дамп раз в месяц плюс инкременты, `YYYY-MM` в имени, обязательный `snapshot`,
  ротация целыми цепочками, восстановление `--restore -i [--at YYYY-MM[-DD]]`.
- **Несколько апстримов**: один дамп или архив уходит во все `targets`,
  у каждого своя ротация и свои ошибки; `--from` сужает отчёты и восстановление.
- **Уведомления** (`notify`): SMTP-почта (`smtplib`), webhook и Telegram.
  `on: [failure|success|always]`, повторы, таймаут; сообщение собирается из
  белого списка (файл сценария, проект, хост, задачи, имена сломанного и
  безопасная причина) — без команд, stderr и ключей.
- **Хуки задачи** `before`/`after`: `/bin/sh -c`, окружение `KWBACKUP_*`,
  общий таймаут `runtime.hook_timeout`; провал `before` отменяет задачу,
  `after` выполняется всегда, его ошибки — предупреждения.
- **syslog** как второй сток: `log.syslog` (`true` или путь к сокету),
  `log.facility`, тег `kwbackup[pid]`; недоступный сокет — предупреждение,
  а не трейсбек посреди бэкапа.
- **`runtime.verbose` / `runtime.debug`** в конфиге: флаги CLI включают тот же
  режим поверх; `log.*` управляет стоками, `runtime.*` — консолью.
- **Живой прогресс упаковки** при `--verbose` в терминале: размер и скорость,
  в `debug` ещё и процент по исходному объёму; в cron/systemd молчит.
- **`--check`** вместо `--check-config`: разобранный конфиг, preflight,
  раскраска, подсказка в списке действий.
- **Выключенные задачи не валидируются на старте**: ошибки копятся в
  `deferred_errors`, список действий помечает `disabled, invalid config`,
  `--check` проверяет всё, а `--force`/`--restore` по задаче — строго.

### Changed

- Терминология: файл YAML — **сценарий**, `database`/`storage`/`archive`/
  `incremental` — **задачи** внутри него.
- `--debug` больше не включает debug в лог-файл: за это отвечает `log.level`.
- `--debug` пишет полные командные строки в лог осознанно — чтобы повторить
  сломанную команду руками; лог держать `0600`, в уведомления это не попадает.

### Fixed

- YAML-ключи больше не преобразуются в булевы: `on:` не превращается в `True`.
- Строка прогресса не оставляет хвост при сокращении и не переносится.
- Пути conffile в `debian/` (`defaults.yaml` и `/etc/default/kwbackup`)
  и упаковка примеров.
- Документация: смысл `dest`, список `sources` любой длины, примеры
  подключения MySQL/PostgreSQL/SQLite, таймлайн `--at`.

### Removed

- `rclone.conf.example`, генератор `debian/changelog`, упоминание systemd
  в инструкции установки.

## [0.99.42] — 2026-11-13

Первая версия на Python. Продолжает bash-линейку (`kwbackup.sh` 0.8.0 …
0.9.0+fix1) как 0.99.x: те же три сценария
и та же схема ротации, но с валидируемым конфигом, честными кодами возврата
и проверкой копий. При выпуске раздел станет `[1.0.0] — <дата>` и получит тег.

### Added

- **Три сценария**: дамп БД → сжатие → заливка; `rclone sync/copy` каталогов;
  `tar` + компрессор → заливка в облако.
- **YAML-конфиг со схемой и валидатором**: неизвестный ключ, неверный тип,
  незаданная переменная окружения — ошибка с путём до ключа.
- **Ротация GFS** с двумя взаимоисключающими правилами на класс:
  `keep: N` (число копий) и `max_age: 7d` (окно по времени).
  `retention_mode` запрещает смешивать правила в одном конфиге.
- **`catch_up`**: пропущенная из-за простоя weekly/monthly копия создаётся
  при следующем запуске (по умолчанию выключено — паритет с 0.9.0).
- **`--list`**: что реально лежит в облаке, размеры, пропущенные дни,
  пустые каталоги, факт устаревания. Код 5 — годится как watchdog.
- **`--verify`**: скачивает копию, сверяет размер, проверяет целостность
  (`zstd -t`, `gzip -t`, `rar t`) и правдоподобность содержимого
  (SQL-заголовок, читаемость tar).
- **`--restore`**: БД, архив и storage в каталог (`--to`), выбор копии
  по `--at`, заливка в живую БД только через `--into-db ... --yes`.
- **`migrate`**: конвертер старого bash-конфига в YAML с сохранением
  глубины хранения (возраст → `keep`).
- **`flock`-блокировки** на `(проект, задача)`; снимаются ядром при любом
  завершении процесса.
- **Preflight**: проверка бинарников, путей, `temp_dir`, `rclone.config`,
  переменной с паролем до начала работы.
- **Три слоя конфигурации**: встроенные дефолты (`src/05_builtin_defaults.py`)
  ← `/etc/kwbackup/defaults.yaml` ← файл задачи. Системный файл — единственный
  путь, который читает программа; каталог скрипта и каталог конфига больше
  не просматриваются. Карты сливаются, списки опций (`rclone.args`,
  `database.args`, `*_compressor_args`, `archive.exclude`) дополняются,
  остальные списки заменяются.
- **`s3-custom-options`**: флаги бэкенда S3 картой без `--`, с типами
  (bool/число/строка) и перекрытием на уровне `rclone` / `database` /
  `storage` / `archive`; `null` снимает унаследованный флаг. Простой путь
  через `rclone.args` сохранён.
- **Ключи S3 по бакету** (BEGET, minio-подобные провайдеры): поддерживаются
  флаги `--s3-access-key-id` / `--s3-secret-access-key` в `rclone.args`,
  потому что при `env_auth = false` переменные `AWS_*` игнорируются.
  Документированы оба варианта — литералы в файле `0600` и `${ENV}` из
  `secrets.env`.
- **`--dry-run`**, **`--check-config`**, **`--selftest`**.
- **Сборка в один файл**: `python3 build.py --test` → `dist/kwbackup`
  с шебангом, без внешних зависимостей (Python 3.10+, только stdlib).
- Документация: `README.md`, `docs/configuration.md`, `docs/usage.md`,
  `docs/migration.md`; примеры конфигов, systemd-юниты, `/etc/cron.d`.
- Сквозные тесты `tests/e2e.py` на фейковом `rclone` (17 сценариев),
  включая валидацию всех `examples/*.yaml` и слияние с файлом дефолтов.

### Changed

- Действие всегда указывается явно: `kwbackup --config file` без
  `--database/--storage/--archive` печатает список действий и ничего не
  запускает.
- Терминал по умолчанию молчит: `info` уходит в лог-файл, на экран — только
  предупреждения и ошибки. `--verbose` показывает `info` и включает
  `rclone --progress`, `--debug` печатает каждую внешнюю команду.
- `-m sync` работает для всех трёх действий и зеркалирует целевой каталог;
  в конфиге для БД и архива допустим только `copy`.
- Ротация удаляет только файлы своего префикса (`<db>_…`, `<name>_…`),
  поэтому общий каталог безопасен для нескольких проектов.
- `archive.name` по умолчанию равен имени проекта, а не `archive`.
- Поле `version` удалено из схемы: расширения совместимы.
- Неизвестный ключ теперь предупреждение, а не ошибка: опечатка видна в
  логе, но старый файл с лишним ключом не останавливает бэкап. Фатальными
  остаются неверные значения и отсутствие обязательных полей.
- Конфиг: исполняемый bash → YAML. Общие настройки вынесены в
  `/etc/kwbackup/defaults.yaml`, файл задачи содержит только отличия.
- Секреты: для бакетных ключей сохраняется механизм флагов rclone
  (`--s3-access-key-id` / `--s3-secret-access-key`); файл с ключами — `0600`.
  Пароли БД передаются через `password_env`.
- Глубина хранения по умолчанию задаётся числом копий (`keep`), а не
  возрастом; старые окна конвертируются мигратором (`43d` → `keep: 6`).
- Архив: `tar -C <root> .` вместо `$root/*` — **dotfiles на верхнем уровне
  больше не теряются**.
- Include-маски архива раскрываются в Python относительно `root`
  (поддержка `**`), а не шеллом, поэтому пробелы в путях безопасны.
- Ротация: сначала заливка, потом удаление старых копий (в 0.9.0 было
  наоборот — `delete --min-age` до `copy`).
- Ошибка любого действия даёт ненулевой код возврата и строку в логе
  с уровнем `error`.
- `--list`/`--verify` выделены в отдельные read-only команды.
- Прогресс через `pv` убран: `--verbose`/`--debug` печатают команды,
  а не прогресс-бар.

### Fixed

Исправлено относительно `kwbackup.sh` 0.9.0:

- `-d -s -a` выполняло **только первое** действие: `((ACTUAL_ACTIONS++))`
  при значении 0 возвращал статус 1 и `errexit` завершал скрипт.
- Lock-файл последней БД **пересоздавался** после `cleanup_action_lock`
  (`echo ... >> "${PROCESS_FLAG_FILE}"`), из-за чего следующий запуск
  молча пропускал бэкап БД навсегда.
- Имя lock-файла не учитывало конфиг (хэш от `$0` + имя действия):
  два проекта на одном хосте блокировали друг друга.
- Все `ERROR`-сообщения уходили в `say`, который печатает только при
  `--debug`, а скрипт при этом возвращал 0.
- PostgreSQL: `pg_dump` получал `"-p 5432"` одним аргументом и падал.
- `-h/--help` возвращал код 1.
- Архив терял `.env`, `.git` и прочие dotfiles на верхнем уровне.
- `ARCHIVE_RAR_INCLUDE_LIST` / `EXCLUDE_LIST` не проверялись на
  существование — `rar @file` падал уже в процессе.
- Мёртвые ключи конфига (`STORAGE_BACKUP_ALGO` перекрывался инициализацией,
  `ARCHIVE_BACKUP_ALGO`, `LOG_FILE`, `DATABASE_SQLITE_OPTIONS` не
  использовались) — убраны или реализованы.

### Removed

- `--reset` и флаги в `/dev/shm`: не нужны с `flock`.
- `--install` / `--self-update` из самого скрипта: установка — `install(1)`,
  обновление — пакет/репозиторий.
- Зависимость от `pv`.
- Списки include/exclude для `rar` отдельным форматом: используются общие
  `include`/`exclude`, работающие с любым компрессором.
